# OpenCode в GitHub Actions

Агент OpenCode работает в репозитории в трёх workflow: по команде в комментарии, при первичном
разборе новых issue и при авто-ревью pull request. Общая настройка — установленное OpenCode GitHub
App, секрет `OPENCODE_API_KEY` и переменные репозитория (см. [Настройка](#настройка)).

## По команде в комментарии

Воркфлоу `.github/workflows/interactive.yml` запускает агента OpenCode по комментарию в issue или
pull request: он разбирает задачу, предлагает изменение и, если попросить, готовит ветку или
pull request.

- **События:** `issue_comment` и `pull_request_review_comment`, только `types: [created]`.
- **Кто запускает:** авторы с ролью `OWNER`, `MEMBER` или `COLLABORATOR`. Комментарии ботов
  игнорируются, поэтому команда в комментарии Dependabot или другого бота запуск не создаёт.
  Комментарий недоверенного участника, в том числе в fork, job не запускает, и секреты остаются
  недоступны.
- **Команды (`MENTIONS`):** `/oc` и `/opencode` в начале комментария или после пробела, в нижнем
  регистре. Переменная задана явно, поэтому набор не зависит от версии OpenCode.
- **Модель:** переменная репозитория `OC_EDIT_MODEL` (например, `opencode/big-pickle`); ключ —
  секрет `OPENCODE_API_KEY`.
- **Share:** `SHARE: "false"` — сессии не публикуются. Для публичного репозитория OpenCode по
  умолчанию включает share, поэтому решение зафиксировано явно.
- **Версия:** OpenCode 1.19.6 ставится в workflow с проверкой SHA-256. Версия закреплена, потому
  что от неё зависит поведение «агент коммитит сам» (см. ниже); action
  `anomalyco/opencode/github` ставил бы последнюю 1.x.
- **Права:** `GITHUB_TOKEN` только на чтение содержимого (`contents: read`), плюс `id-token: write`
  для обмена OIDC на токен OpenCode GitHub App; этим токеном агент отвечает в треде и создаёт
  ветки и pull request. `issues: write` нужен `gh` внутри агентской сессии: там `GH_TOKEN` —
  это `GITHUB_TOKEN`, поэтому операции с issue идут от его имени. `pull-requests: write` нужен
  для служебного комментария с бюджетом: запись в pull request GitHub авторизует по этому scope,
  `issues: write` для неё недостаточно. `actions/checkout` работает с `persist-credentials: false`.
- **Лимиты:** таймаут job — 30 минут; `concurrency` на issue или PR: одновременно выполняется
  один запуск, следующий ждёт в очереди, текущий не отменяется.

**Бюджет запросов.** Переменная репозитория `OC_CHAT_LIMIT` (по умолчанию `3`) ограничивает число
запросов человека к агенту в одном pull request. Бюджет действует только на pull request: `/oc` в
обычном issue не ограничивается.

- Считается каждый **допущенный** запрос: команда из общего треда и из построчного комментария
  использует один и тот же счётчик PR.
- Счётчик хранится в служебном комментарии `<!-- oc-chat-budget: N -->` и сохраняется между
  запусками; в issue такой комментарий не создаётся. Счётчик увеличивается **после** успешного
  завершения шагов checkout и установки OpenCode, но **перед** запуском модели. Это гарантирует,
  что бюджет тратится только на попытки, которые действительно достигают модели. Отмена и таймаут
  после начала выполнения модели расходуют попытку.
- Запрос сверх лимита не меняет счётчик, не доходит до модели и получает короткий ответ о том, что
  бюджет исчерпан.
- Нецелое значение `OC_CHAT_LIMIT` — ошибка конфигурации: job завершается с ошибкой, модель не
  вызывается. Значение `0` полностью выключает запуск по команде.
- **Сброс:** отредактируйте число в служебном комментарии на `0` или удалите комментарий. Следующий
  `/oc` начнёт отсчёт заново. Новый PR получает новый бюджет автоматически.

**Коммит.** Агент сам создаёт коммит на текущей ветке по Conventional Commits (`AGENTS.md`) и не
оставляет незакоммиченных изменений. OpenCode только пушит его: собственное сообщение OpenCode —
пересказ ответа короче 40 символов, его нельзя настроить, и оно не проходит `commitlint`.
Ветку агент не переключает: при смене ветки OpenCode пропускает push. Заголовок pull request,
созданного из issue, по-прежнему остаётся пересказом OpenCode; при squash многокоммитного pull
request его нужно поправить вручную, при rebase сообщения коммитов сохраняются.

**Результат.** Агент отвечает комментарием в том же треде, а при необходимости создаёт ветку и
pull request. Статус и логи запуска — на вкладке Actions, workflow `interactive`.

## Авто-triage новых issue

Воркфлоу `.github/workflows/triage.yml` запускает первичный разбор новых issue.

- **Событие:** `issues`, только `types: [opened]`.
- **Кто проходит фильтр:** автор — не бот, и аккаунт создан не менее 30 дней назад. Issue,
  созданные ботами или слишком новыми аккаунтами, не обрабатываются.
- **Пропуск подготовленных тикетов:** если у issue уже есть лейбл `needs-triage`, `needs-info`,
  `ready-for-agent`, `ready-for-human`, `wontfix` или любой лейбл с префиксом `wayfinder:`,
  повторный разбор не запускается.
- **Модель:** `opencode/big-pickle` — задана прямо в workflow; ключ — секрет `OPENCODE_API_KEY`.
- **Share:** `SHARE: "false"` — сессии не публикуются.
- **Версия:** OpenCode 1.19.6 ставится в workflow с проверкой SHA-256. Версия закреплена, потому
  что composite action `anomalyco/opencode/github` ставил бы последнюю 1.x, а от версии зависит
  поведение `opencode github run`.
- **Только чтение:** `OPENCODE_PERMISSION` запрещает `edit` и `bash`. Поэтому агент не может
  изменить рабочее дерево, и `opencode github run` не создаёт коммит и pull request. Инструкция
  в prompt — не единственная защита: собственное сообщение OpenCode короче 40 символов не
  проходит `commitlint`.
- **Права:** `GITHUB_TOKEN` только на чтение (`contents: read`), плюс `id-token: write` для
  обмена OIDC на токен OpenCode GitHub App. `actions/checkout` работает с
  `persist-credentials: false`.
- **Лимиты:** таймаут job — 30 минут; глобальная `concurrency`-группа `oc-triage`:
  одновременно выполняется один triage-запуск, следующие ждут в очереди, текущий не отменяется.

**Результат.** Агент читает issue и контекст репозитория и, если может дать полезное объяснение,
оставляет комментарий с кратким разбором, а при наличии — с очевидным направлением фикса,
ссылками на документацию или места в коде. Если понятного объяснения нет, комментарий не создаётся.
В этом запуске агент не меняет файлы, не создаёт ветки и pull request,
не меняет лейблы и не закрывает issue: `edit` и `bash` запрещены через `OPENCODE_PERMISSION`.
Статус и логи — на вкладке Actions, workflow `triage`.

## Авто-ревью pull request

Воркфлоу `.github/workflows/pr-review.yml` автоматически ревьюит PR по протоколу `REVIEW.md`:
проверяет дифф, связанную задачу и результаты CI, а затем публикует комментарий с вердиктом и
замечаниями. Агент не меняет файлы, не создаёт коммиты, не апрувит и не мержит PR.

- **События:** `pull_request` — `opened`, `synchronize`, `reopened`, `ready_for_review`.
- **Кто проходит фильтр:** PR не draft, создан из ветки этого же репозитория (PR из fork
  пропускаются), автор — владелец репозитория или `opencode-agent[bot]`.
- **Бюджет:** переменная `OC_REVIEW_LIMIT` (по умолчанию `10`). Считаются все попытки запуска в
  истории Actions для этого PR, включая ре-раны, отмены и таймауты; при исчерпании модель не
  вызывается. История запусков должна сохраняться — удаление запусков сбрасывает счётчик, а новый
  PR получает новый бюджет. Нецелое значение — ошибка конфигурации с причиной `infra`. Этот бюджет
  не связан с бюджетом команд `/oc` в `interactive.yml`.
- **Модель:** переменная репозитория `OC_REVIEW_MODEL`; ключ — секрет `OPENCODE_API_KEY`. Если
  хотя бы одно значение не передано, job завершается с причиной `infra`, и модель не вызывается.
- **Доступ агента:** OpenCode запускается с `--agent plan` и запретом на правки (`edit: deny`);
  из bash разрешены только `gh` для чтения PR, проверок и запусков и `git` для диффа, истории и
  статуса. Текст PR, комментарии и код считаются данными, а не инструкциями.
- **Права:** `contents`, `issues`, `actions`, `checks` и `statuses` — только чтение;
  `pull-requests: write` нужен для комментариев с ревью и итогом. `actions/checkout` работает с
  `persist-credentials: false`.
- **Лимиты:** таймаут job — 15 минут; вызов модели ограничен 5 минутами после установки
  OpenCode 1.19.6 (закреплена и проверяется по SHA-256). `concurrency` на PR: новый запуск
  отменяет предыдущий.

**Результат.** При успехе агент публикует комментарий с вердиктом по формату `REVIEW.md`. Если
модель не отработала — исчерпан бюджет, истёк таймаут, сбой установки, ключа или агента, —
отдельный job `report` публикует комментарий «нужен человек» с причиной, последним SHA и ссылкой
на логи. Автоматического цикла исправлений нет: следующее действие выбирает человек. Статус и
логи — на вкладке Actions, workflow `pr-review`.

## Настройка

Установите OpenCode GitHub App на репозиторий и добавьте секрет `OPENCODE_API_KEY`
(*Settings → Secrets and variables → Actions*). Переменные репозитория:

- `OC_EDIT_MODEL` — модель для запуска по команде в комментарии;
- `OC_CHAT_LIMIT` — число запросов к агенту на один pull request в `interactive.yml`
  (по умолчанию `3`);
- `OC_REVIEW_MODEL` — модель для авто-ревью PR;
- `OC_REVIEW_LIMIT` — число попыток авто-ревью на один PR (по умолчанию `10`).

Модель triage задана прямо в `triage.yml`.
